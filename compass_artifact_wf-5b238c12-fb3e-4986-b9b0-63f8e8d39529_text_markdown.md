# TRUE TOP-K PROOF — Invention Run for MNEME: Prior-Art Verdict, Candidate Constructions, and a Prototype-Ready Survivor

## TL;DR
- The target (sublinear-verifier proof of EXACT top-k NN in high dimension, no trusted setup, ≤10 KB / microseconds at n=10k) does NOT exist in public literature; every close system (V3DB, zkRAG, VeriRAG, VeriANN, ANNProof) proves *procedure-faithfulness over an approximate index* (HNSW/IVF-PQ replay), explicitly not exactness — so MNEME's honesty caveat stands today.
- The strongest survivor is Candidate (b): a **threshold-count sum-check** that proves COUNT(i : dist(q,v_i) ≤ d_k) = k AND COUNT(< d_k) < k over committed quantized integer vectors — this folds the negative ("no un-returned vector is closer") into ONE counting statement with a linear prover and a logarithmic-round sum-check, but it is **not free of a multilinear polynomial commitment**: the final sum-check evaluation forces a transparent PCS opening, so the honest minimum-viable proof is ~hundreds of KB to single-digit MB at n=10k, NOT ≤10 KB.
- Honest bottom line: the ≤10 KB / microsecond verifier target is **not simultaneously achievable** with a single self-contained cryptographic proof under no trusted setup at n=10k; it IS achievable under a different trust model — Candidate (e) optimistic/refereed verification, where the at-rest "proof" is a bond + challenge window and a single fraud-proof costs one Merkle path + one distance recomputation. The run produced recombination, not discovery: the novelty-delta is the exactness reframing (quantized-metric exact top-k via count-sum-check) versus the procedure-faithfulness systems that dominate the literature.

## Key Findings

**Phase 0 verdict — the target is not solved.** The 2024–2026 verifiable-vector-search cluster is large and active, but uniformly proves a weaker statement than MNEME needs:
- **V3DB** (Qiu, Qu, Zhang, Yuan, arXiv 2603.03065) proves the output "is exactly the result of executing the published [IVF-PQ] semantics on the committed snapshot" — i.e., faithful execution of an *approximate* pipeline. Verbatim: "Our prototype implementation based on Plonky2 achieves up to 22× faster proving and up to 40% lower peak memory consumption than the circuit-only baseline, with millisecond-level verification time." It does not prove the returned items are the true nearest neighbors.
- **zkRAG** (Jiang et al., IACR 2026/709) gives "the first polynomial interactive oracle proof (PIOP) tailored to the widely deployed HNSW ANNS algorithm," proving "the returned results must be consistent with executing an agreed approximate nearest neighbor search (ANNS) algorithm." Benchmark on SIFT1M (N=10^6, d=128): "the prover time is about 50s, which is about 1000× faster than baselines... The verifier time is 1s, and the proof size is 0.5MB" (baselines HyperPlonk and SP1). Explicitly approximate.
- **VeriRAG** (Lin et al., IACR 2026/637) "supports Approximate Nearest Neighbor Search (ANNS)-based retrieval to avoid exhaustive searches"; verbatim: "VeriRAG scales efficiently to a 37GB dataset, achieving a prover time of 96s and a verifier time of 3s." Approximate.
- **VeriANN** (IACR 2026/923) is the "first encrypted ANN retrieval framework" confirming top-k identifiers "were produced by faithfully executing an agreed approximate nearest neighbor (ANN) algorithm." Approximate.
- **ANNProof** (Future Generation Computer Systems, 2024) uses a Merkle-HNSW ADS (Merkle HNSW node tree + Merkle vector identifier tree) for verifiable outsourced K-ANNS on blockchain. Approximate.
- Database-outsourcing ADS line (Yiu/Cheng "Query assurance verification for outsourced multi-dimensional databases", JCS 2009; MR-trees; VoR-trees; spatial top-k by Hu/Ku "Spatial Query Integrity with Voronoi Neighbors", TKDE 2013) does achieve *exact* completeness/soundness for kNN, but only in LOW-dimensional spatial settings (2D/3D, road networks), via Voronoi-neighbor verification objects. Verification cost and VO size grow with the boundary of the search region, which blows up in high dimension. None achieves sublinear verification for exact kNN in d=128–768.

So nothing comes within 2× of the target for EXACT high-dimensional top-k with a sublinear verifier and no trusted setup. The closest *exact* work is low-dimensional spatial ADS; the closest *high-dimensional* work proves only procedure-faithfulness over an approximate index.

**The lower-bound reality the prover must respect.** Exact NN in high dimension is hard for the PROVER regardless of proof technology: cell-probe / communication lower bounds (Borodin–Ostrovsky–Rabani; Barkol–Rabani; Pătrașcu) and the metric-tree bound (arXiv 0812.0146: any data structure with d^O(1) query time needs n^ω(1) space) mean there is no sublinear-work *search*. Critically for us, a recent paper (arXiv 2503.03079, "Sublinear Data Structures for Nearest Neighbor in Ultra High Dimensions") proves a one-way communication lower bound: "If Alice sends a sketch of her centres from which Bob can exactly compute the nearest neighbour … Alice needs to send at least Ω(nd) bits." This constrains *sketch-then-decide* (statistical/coded) candidates, but does NOT constrain an interactive proof where the prover does honest linear work and only the verifier must be sublinear. Sum-check-based IPs are exactly the escape hatch: prover does O(n·d) honest work; verifier does O(log n) — consistent with all lower bounds because the prover is not sublinear.

**The key building blocks all exist and are transparent.** Sum-check (LFKN 1992) has soundness error d·v/|F| (Thaler, *Proofs, Arguments, and Zero-Knowledge*: "with soundness error at most ℓ·d/|F|"); for degree-2/3 over v=17 variables in 64-bit Goldilocks this is ≈ 2^−59 (a single instance), needing an extension field or repetition for 128-bit security. GKR/Libra (Xie et al., CRYPTO 2019) gives linear-prover circuit evaluation (253 KB proof, 50 ms verifier on its SHA2-Merkle benchmark, but Libra requires an input-dependent setup — not transparent). Lasso (Setty–Thaler, IACR 2023/1216) gives transparent range-checks/lookups with prover cost dominated by committing 3·c·m + c·n^{1/c} small field elements. Transparent multilinear PCS exist: Brakedown (linear prover, O(√n) proof/verifier, field-agnostic, plausibly post-quantum), Ligero, Binius/FRI-Binius, Orion (O(log²n) proof). Spartan (CRYPTO 2020) composes these into a transparent zkSNARK with sub-linear verification.

**Why the scalar top-k ADS does not transfer.** Sorted-Merkle-Tree top-k (SMT-based ADS, FGCS 2024) gets exact top-k with VO = O(k log n) and Merkle-path verification — but it relies on a *total order on a single committed scalar attribute*. A NN query computes a *fresh per-query scalar* dist(q,v_i) that is not known at commit time, so there is no pre-sortable order; the boundary/negative cannot be read off a static sorted tree. This is precisely the gap.

**Voronoi route and why it explodes.** A Voronoi cell certificate proves 1-NN in low dimension by exhibiting the cell containing q. But the worst-case combinatorial complexity of a Voronoi diagram of n points in R^d is Θ(n^⌈d/2⌉) (standard; arXiv 1401.1477: "in higher dimensions the complexity is Θ(n^⌈d/2⌉)"). Empirically (arXiv 2405.10050, HighVoronoi.jl) the expected vertices/cell for uniform points grows superexponentially: 6.6 (d=2), 191 (d=4), 9720 (d=6), 91900 (d=7) — "the sheer amount of vertices … somewhere around d>10, will prohibit a solution." So authenticated-Voronoi (Candidate d) is dead beyond d≈10 unless intrinsic/doubling dimension is low.

**Phase 0 verdict.** The target does not exist. The exact-vs-approximate gap is the crux: high-dimensional verifiable-NN systems are ALL approximate-procedure proofs; exact systems are ALL low-dimensional or scalar-attribute. MNEME's caveat ("recall receipts prove the declared procedure ran, not that returned items are true nearest neighbors") is presently accurate and unbeaten.

### PHASE 1 — Five candidate constructions

**(a) Tropical / min-plus sum-check.** Express min-distance as evaluation in the (min,+) semiring; try to verify a claimed min via a Freivalds-style or sum-check-style protocol. Core trick: the "no closer vector" negative is the statement min_i dist(q,v_i) = d_min. Why it might work: certifying-algorithms theory (McConnell–Mehlhorn–Näher–Schweitzer, Computer Science Review 2011) shows a min/argmin is trivially certified by exhibiting the witness index PLUS a separation certificate that all others are ≥. Most obvious attack / fatal flaw: sum-check is fundamentally algebraic over a *field*; the tropical semiring has no additive inverse ("Negating a tropical number … will raise an error"), so the multilinear-extension + Schwartz–Zippel machinery does not port — there is no low-degree-extension soundness in (min,+). The "separation certificate" for a global min over n committed items is itself n inequalities, i.e., linear verifier unless folded into a field-based counting argument — which is just Candidate (b). Building blocks: min-plus matrix product has no truly subcubic algorithm (verification ≠ computation, but verification of a claimed min still needs the n separations).

**(b) Threshold-decomposition + sum-check count (LEAD CANDIDATE).** Commit the n quantized integer vectors. Prover returns k indices S and the claimed k-th distance d_k. Prove the negative as TWO counting statements over a committed indicator:
- COUNT(i : dist(q,v_i) ≤ d_k) = k  (nothing outside S is ≤ d_k, i.e., completeness of the boundary), and
- COUNT(i : dist(q,v_i) < d_k) = k−(#ties to release) with index-order tie-breaking, plus a check that the k returned indices are exactly the qualifying set.

Each COUNT is a sum over n Boolean indicators b_i = [dist(q,v_i) ≤ d_k], provable in ONE sum-check: Σ_{i∈{0,1}^{log n}} b̃(i) = k. The comparison b_i is enforced by bit-decomposing the (integer) distance and range-checking via Lasso/logUp lookups; the distances dist(q,v_i) = ‖q‖²+‖v_i‖²−2⟨q,v_i⟩ fold into the same arithmetization because the inner product is a sum that GKR/sum-check proves natively. Why it works: the negative becomes a single global count; prover is O(n·d) honest work; the sum-check verifier is O(log n) field ops. Most obvious attack: forgery by omission requires making the indicator lie about some hidden closer vector, but the indicator is tied to the committed data through the final MLE opening — so a lie is caught by the PCS opening / sum-check final check (analyzed in Phase 2). Building blocks: sum-check (LFKN), GKR/Libra for the inner products, Lasso (2023/1216) for range checks, Spartan + Brakedown/Ligero/Binius for the transparent multilinear PCS.

**(c) List-decoding / locally testable distance codes.** Encode each vector so distance relations are locally testable; verifier samples few coordinates (JL projection + AMS sketch concentration) to gain statistical confidence no un-returned vector is closer. Core trick: random projection preserves distances; verifier checks a few sketched coordinates. Most obvious attack: the Ω(nd) one-way communication lower bound (arXiv 2503.03079) says any *sketch* enabling exact NN decision needs Ω(nd) bits — so exactness via sketching is impossible at sublinear size. Soundness is only statistical and an adaptive adversary who knows the projection can plant a vector that ties in the sketch but differs in truth. Kill candidate (Phase 2).

**(d) Authenticated Voronoi-lite / cover trees.** Precompute authenticated ball-cover certificates (cover trees, navigating nets) so exactness reduces to O(2^O(dim) log n) authenticated ball-emptiness checks. Works only when doubling/intrinsic dimension is low. Most obvious attack / flaw: at d=768 (and even d=128) ambient dimension, the 2^O(dim) factor and Voronoi Θ(n^⌈d/2⌉) blowup make certificates exponentially large. Measured embedding intrinsic dimensions sit in the low tens, not single digits: Tulchinskii et al. (arXiv 2306.04723) report persistent-homology intrinsic dimension ≈9.2–12.1 for RoBERTa-base text embeddings (Wikipedia 9.49±1.01, fiction 9.21±1.29, QA 9.59±1.29); "Measuring Intrinsic Dimension of Token Embeddings" (arXiv 2503.02142) reports GloVe ID=24.77, Word2Vec=24.75, FastText=13.19 — far above the single-digit doubling dimension this candidate needs. Kill candidate.

**(e) Mechanism-design / economic soundness (STRONG ALTERNATE).** Optimistic verification: prover posts top-k + bond; a challenge window opens; any watcher can submit ONE counterexample vector v_j with its Merkle membership proof and a recomputed distance showing dist(q,v_j) < d_k, which slashes the bond. Verification of a CHALLENGE = one Merkle path + one distance computation — squarely within the 10× target. The "proof at rest" is a bond + time window, not a cryptographic object. Trust model: 1-of-N honest watcher (refereed-delegation / optimistic-rollup model; Feige–Kilian refereed games, Canetti–Riva–Rothblum RDoC, Arbitrum, TrueBit). Most obvious attack: data-availability — a watcher must be able to read all n committed vectors to find the counterexample (the linear work moves to the watcher, off the verifier's critical path); and liveness/censorship of challenges. Patchable with bonded watchers and DA guarantees, but it is a DIFFERENT trust assumption than cryptographic soundness.

**(f) Hybrid / honest reframing.** Quantize embeddings to fixed-point integers so distances are EXACT field elements (floating point breaks field arithmetic). Then "exact top-k" honestly means "exact top-k under the committed quantized metric" — an honest reframing MNEME can adopt. Amortize by committing distances/norms once per epoch; queries reuse the commitment. This is the realistic packaging of (b).

### PHASE 2 — Attack phase (≥3 kills)

**KILL 1 — Candidate (a) tropical sum-check.** Fundamental, not patchable. Sum-check soundness derives from the Schwartz–Zippel lemma over a field; the (min,+) semiring is not a field (no additive inverses, idempotent addition), so there is no low-degree extension and no random-point identity test. Any "tropical sum-check" collapses to exhibiting n separations = linear verifier. Dead.

**KILL 2 — Candidate (c) coded/statistical.** Fundamental. The one-way communication lower bound Ω(nd) bits for exact NN decision (arXiv 2503.03079, Lemma G.3) means no sublinear sketch yields *exact* soundness. Adaptive quantization-boundary attack: adversary plants v* whose JL-projected sketch ties at d_k but whose true distance is smaller; per-query statistical soundness cannot be made exact and degrades under adaptive queries that learn the projection seed (grinding the Fiat-Shamir transcript). Dead for EXACT; survives only as a heuristic recall booster.

**KILL 3 — Candidate (d) authenticated Voronoi-lite.** Fundamental at high ambient d, patchable only under a low-doubling-dimension assumption that MNEME embeddings do not satisfy (measured text-embedding intrinsic dimension is ≈9–25, not single-digit; arXiv 2306.04723, 2503.02142). Voronoi complexity Θ(n^⌈d/2⌉) and superexponential vertices/cell (91900 at d=7) make certificates explode. The attack is simply dimension: at d=128 the certificate is astronomically large. Dead for general embeddings.

**Attacks on the survivors (b) and (e):**
- **(b) forgery by omission:** Adversary hides a closer vector v* by committing an indicator b that under-counts. Caught because the count sum-check's final step requires opening the multilinear extension of the *committed distances/data* at a random point r; a fabricated indicator inconsistent with the committed v* fails the MLE opening with probability 1 − d·v/|F| ≈ 1 − 2^−59 per instance. Patchable to 2^−128 via extension-field challenges or repetition. **Not a kill.**
- **(b) quantization-boundary / tie attack:** A vector whose true real-valued distance ties at d_k could be included or excluded ambiguously. Resolved by the honest reframing (f): define the statement over the committed quantized integer metric with deterministic tie-break by index order, so ties are well-defined. Residual issue: quantization can change the *real* top-k (an item ranked k+1 in real distance may rank ≤k in quantized distance). This is an HONESTY caveat MNEME must publish, not a soundness break. **Not a kill; it is a scope statement.**
- **(b) prover equivocation between epochs / grinding the commitment:** Standard — bind the commitment root and the query into the Fiat-Shamir transcript; a fixed snapshot commitment prevents cross-epoch equivocation. **Not a kill.**
- **(b) the real killer — cost, not soundness:** The final sum-check evaluation strictly requires a multilinear PCS opening. A bare Merkle root is binding to the data but is NOT homomorphic and gives no MLE-at-r evaluation proof — so the verifier cannot avoid a PCS (confirmed by Spartan Thm 5.1, which requires "an extractable polynomial commitment scheme for multilinear polynomials" as a mandatory ingredient). With transparent code-based PCS (Brakedown/Ligero) at n=10k–2^20, proof size is O(√n) and verifier is O(√n); Spartan itself notes that among transparent SNARKs it "produces proofs that are shorter by 1.2–416×" yet the sub-√n-proof Hyrax/Spartan-DL variants "achieve sub-sqrt proofs at the cost of increasing V's time" — i.e., the O(√n) opening floor is inherent. Concretely this lands at hundreds of KB to single-digit MB and verifier in the low-ms range at n=10k, NOT ≤10 KB / microseconds. So (b) MEETS the soundness and no-trusted-setup goals but MISSES the ≤10 KB / microsecond targets by 1–2 orders of magnitude at n=10k. **This is the honest result: the target's size/time bound is not met by a self-contained transparent proof.**
- **(e) data-availability / liveness:** Fundamental to the optimistic model — if the committed vectors are withheld, no watcher can construct a fraud proof. Patchable with DA commitments and bonded watchers, but the trust assumption (1-of-N honest, plus DA) is strictly weaker than cryptographic soundness. **Not a kill, but a different model.**

### PHASE 3 PREP — Prototype-ready spec for the survivor

**Two-tier recommendation.** Ship Candidate (e) (optimistic) as the *deployable* layer that meets the ≤10 KB / microsecond verifier bound (challenge = 1 Merkle path + 1 distance recompute), and prototype Candidate (b) (count-sum-check) as the *cryptographic* layer that meets soundness + no-trusted-setup but with honest-larger proofs. The forgery test below targets (b).

**Exact statement proven (b).** "The k returned indices are exactly those with the k smallest quantized distances to q among the n committed vectors, ties broken by ascending index order," under the committed quantized metric.

**Field.** Goldilocks p = 2^64 − 2^32 + 1 for fast 64-bit arithmetic; draw Fiat-Shamir challenges from a degree-2 or degree-3 extension (≈128-bit) to lift the single-instance soundness from ≈2^−59 to ≈2^−118.

**Quantization.** Map each d=128 embedding coordinate to a b-bit fixed-point integer (b=16 is ample; ‖q−v‖² then fits in ≈ 2b + log d ≈ 39 bits, well inside Goldilocks). Distances are exact integers in-field. "Exact" = exact under this committed quantized metric.

**Commitment.** Commit the n×d quantized matrix as a multilinear polynomial via a transparent PCS (Brakedown for linear prover; Binius/FRI-Binius if small-field efficiency matters). The MNEME Merkle root remains the data anchor; the PCS is layered on the same encoded matrix.

**Protocol message flow (Fiat-Shamir, non-interactive):**
1. Setup/commit (per epoch): publish PCS commitment C to the quantized matrix; bind C to MNEME's signed Merkle root.
2. Query: verifier sends q (or its quantized form) + transcript seed.
3. Prover returns: k indices S, the k distances, claimed boundary d_k, and a proof π containing (i) a GKR/sum-check transcript for the inner products ⟨q,v_i⟩ → distances, (ii) Lasso range-check transcripts for the bit-decomposed comparisons [dist ≤ d_k], (iii) the count sum-check Σ b̃(i) = k, and (iv) one batched multilinear-PCS opening at the random point r.
4. Verify: check the sum-check rounds (O(log n) field ops), the lookup/range arguments, the count = k, and the single PCS opening.

**Polynomial identities to implement.**
- Distance: D_i = Q2 + N_i − 2·IP_i, where N_i = ‖v_i‖² (committed once per epoch), IP_i = ⟨q, v_i⟩, Q2 = ‖q‖² (public).
- Inner product as sum-check: ĨP(i) = Σ_{j∈{0,1}^{log d}} q̃(j)·ṽ(i,j).
- Indicator: b_i = [D_i ≤ d_k]; enforce via D_i = d_k − slack_i with slack_i ≥ 0 range-checked (Lasso), and a symmetric strict-version for the < count.
- Count: Σ_{i} b̃(i) = k (one sum-check); plus a permutation/lookup check that S equals the qualifying index set with index-order tie-break.

**Costs.**
- Prover: O(n·d) field ops for distances + O(n·b) for range checks + O(n) PCS commit ≈ O(n·d). At n=10k, d=128: ~1.3M multiply-adds — sub-second in Rust.
- Verifier: sum-check O(log n + log d) ≈ tens of field ops (microseconds) PLUS the PCS opening verification, which dominates: O(√n) for Brakedown/Ligero (hundreds of µs–low ms at n=10k) or O(log²n) for Orion.
- Proof size: sum-check transcript O(log n) ≈ a few KB; PCS opening dominates — Brakedown O(√n): on the order of 100s of KB at n=10k. As reference asymptotics, Spartan's transparent proofs are "shorter by 1.2–416×" than peers but the sub-√n variants trade proof size for verifier time, so the O(√n) floor holds. **≤10 KB is not met; honest expectation is ~100 KB–low MB.**

**Toy-scale honest parameters.** n=10k, d=16–128, k=10, b=16-bit quantization, Goldilocks + degree-2 extension challenges.

**Libraries to prototype fast.** Pure-Python sum-check over a small prime is acceptable for the forgery test (e.g., Justin Thaler's reference pseudocode; lambdaworks/arkworks for Rust; Microsoft Spartan (github.com/microsoft/Spartan) for the transparent SNARK; the Lasso/Jolt codebase for range checks; Binius (github.com/IrreducibleOSS/binius) for small-field PCS). The zk-IVF-PQ repo (github.com/TabibitoQZP/zk-IVF-PQ, from V3DB) is a useful structural reference but proves the approximate pipeline.

**Forgery-test design.** (1) Build a committed set of n=10k quantized vectors; pick query q. (2) Compute true quantized top-10 honestly; generate proof; confirm verifier ACCEPTS. (3) Plant a closer vector v* (quantized distance < d_k), OMIT it from S, and have the prover attempt a proof claiming the original top-10. (4) Assert the count sum-check / PCS opening makes the verifier REJECT with probability ≥ 1 − 2^−100. (5) Tie attack: plant v* with quantized distance exactly d_k and verify deterministic index-order tie-break behaves as specified.

### PHASE 4 PREP — Claims ledger

- **PROVEN-IN-LITERATURE:** All close systems are approximate-procedure proofs (V3DB 2603.03065; zkRAG 2026/709 — 50 s prover / 1 s verifier / 0.5 MB on SIFT1M; VeriRAG 2026/637 — 96 s prover / 3 s verifier; VeriANN 2026/923; ANNProof FGCS 2024). Sum-check soundness d·v/|F| (LFKN 1992; Thaler PAZK, "ℓ·d/|F|"). Lasso prover cost (2023/1216). Brakedown linear prover, O(√n) proof/verifier, transparent (CRYPTO 2023). Spartan transparent sub-linear verifier with mandatory multilinear PCS (CRYPTO 2020, Thm 5.1). Libra 253 KB / 50 ms but non-transparent (CRYPTO 2019). Voronoi complexity Θ(n^⌈d/2⌉) (arXiv 1401.1477). Ω(nd) one-way communication for exact NN (2503.03079). Embedding intrinsic dimension ≈9–25 (arXiv 2306.04723, 2503.02142). Refereed delegation / RDoC (Feige–Kilian; Canetti–Riva–Rothblum). Certifying algorithms (McConnell et al. 2011).
- **DERIVABLE-ON-PAPER:** Candidate (b)'s reduction of the top-k negative to two COUNT sum-checks over committed indicators with Lasso range-checks; folding inner products into the same arithmetization; the conclusion that a bare Merkle root cannot replace a multilinear PCS for the final opening (derivable from sum-check structure + non-homomorphism of hash commitments — corroborated by Spartan Thm 5.1). The concrete proof-size/verifier estimates at n=10k (extrapolated from published Spartan/Brakedown asymptotics).
- **CONJECTURE:** That no transparent, self-contained cryptographic proof can simultaneously hit ≤10 KB AND microsecond verification for exact top-k at n=10k (CONJECTURE — strongly suggested by the O(√n) PCS-opening floor and the absence of any constant-size transparent multilinear PCS without trusted setup, but not a formal impossibility theorem; a trusted-setup KZG-based system could shrink proofs to ~O(1) at the cost of violating the no-trusted-setup requirement).

**Novelty-delta.** The surviving construction (b) "differs from V3DB/zkRAG/VeriRAG [closest prior work] because it proves an EXACT top-k boundary via a global threshold-COUNT sum-check over committed quantized distances, rather than proving faithful replay of an approximate HNSW/IVF-PQ index traversal." This is a recombination of existing primitives (count sum-check + Lasso range-checks + transparent PCS) applied to the exactness statement, not a new cryptographic primitive. **The run found recombination, not discovery.**

(c) If a trusted setup becomes acceptable, a KZG-based count argument gives ~O(1) proofs and constant verifier — switch immediately.

## Caveats
- The ≤10 KB / microsecond target and the no-trusted-setup constraint are in tension at n=10k; this report concludes (with one explicit CONJECTURE tag) they are not jointly met by a self-contained cryptographic proof, only by the optimistic model.
- "Exact" throughout means exact under the committed quantized integer metric; floating-point exactness is not provided and is not well-defined in field arithmetic.
- The concrete proof-size and verifier-time numbers at n=10k are extrapolations from published asymptotics/tables at 2^16–2^20 over different (often ~256-bit curve) fields; treat as order-of-magnitude, not measured at MNEME's exact parameters.
- Single-instance sum-check soundness over 64-bit Goldilocks (~2^−59) is below a 128-bit target; the spec lifts this via extension-field challenges/repetition, which must be implemented correctly.
- The optimistic model's soundness rests on data availability and at least one honest, funded watcher — assumptions outside pure cryptography.
- zkRAG/VeriRAG/V3DB numbers cited are from their own evaluation sections and are for the *approximate* statement; they are not directly comparable to an exact-top-k prover, which must touch all n vectors.
